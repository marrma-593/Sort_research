# 排序算法的实验研究

基于 C++ 模板实现的六种经典内部排序算法实验平台。项目统一了算法调用接口，精确统计排序过程中的**元素比较次数**与**赋值次数**，并在多种数据分布、数据规模和数据类型下进行性能对比，最后通过 Jupyter Notebook 生成可视化图表。

## 功能概览

- **六种排序算法**：冒泡排序、选择排序、快速排序、插入排序、希尔排序、桶排序
- **精确操作计数**：通过引用传参统计比较次数和赋值次数，不依赖全局变量
- **多种数据分布**：完全逆序、完全顺序、均匀分布、正态分布
- **多种数据规模**：1024 到 262144，逐次倍增，共 9 个等级
- **三种数据类型**：`int`、`double`、`Score` 结构体
- **C 字符串专项实验**：对比二维定长数组与指针数组两种存储方式的排序性能
- **正确性校验**：每次排序后检查结果是否为升序
- **可视化分析**：时间曲线、操作次数曲线、分组柱状图、鲁棒性热力图等

## 算法一览

| 算法     | 平均时间复杂度 | 空间复杂度 | 稳定性 | 主要瓶颈        |
| -------- | -------------- | ---------- | ------ | --------------- |
| 冒泡排序 | O(N²)         | O(1)       | 稳定   | 赋值 / 交换     |
| 选择排序 | O(N²)         | O(1)       | 不稳定 | 比较            |
| 插入排序 | O(N²)         | O(1)       | 稳定   | 赋值 / 数据移动 |
| 快速排序 | O(N log N)     | O(log N)   | 不稳定 | 比较与递归      |
| 希尔排序 | 约 O(N^1.3)    | O(1)       | 不稳定 | 比较与赋值      |
| 桶排序   | O(N + K)       | O(N + K)   | 稳定   | 分桶与收集      |

> 本仓库中希尔排序采用增量折半（`gap /= 2`），桶排序的桶数取数据规模 N。

## 编译与运行

### 环境要求

- Linux / WSL2
- GNU G++，支持 C++11
- 建议使用 Release 级别的优化以缩短大规模数据测试时间

### 编译

```bash
g++ -std=c++11 -O2 Main.cpp MyRand.cpp Score.cpp SortString.cpp -o Sorts
```

### 运行

```bash
./Sorts
```

完整实验包含 4 种分布 × 9 种规模 × 6 种算法，耗时约 **15 分钟**。也可以使用脚本运行并保存结果：

```bash
./run.sh
```

脚本会把带时间戳的运行结果追加到 `results_release.txt`。

> 在 `int` / `double` 测试中，当数据规模 `N ≥ 32768` 时，程序会跳过冒泡排序和快速排序（前者耗时过长，后者存在递归过深导致栈溢出的风险），对应时间与计数记为 `-1`。

## 测试与实验设计

### 数据分布

| 编号 | 分布     | 说明                                           |
| ---- | -------- | ---------------------------------------------- |
| 0    | 完全逆序 | 从大到小严格递减，模拟最不利情况               |
| 1    | 完全顺序 | 从小到大严格递增，测试算法对有序输入的识别能力 |
| 2    | 均匀分布 | `[54, 90]` 上的均匀随机数据                  |
| 3    | 正态分布 | 均值 72、标准差 6，模拟成绩类数据              |

### 测试流程

1. `InitData()` 生成原始数据并保存到 `data0`
2. `ReSet()` 将 `data0` 复制到工作数组 `data`，保证各算法输入完全一致
3. `Reset_counters()` 将比较计数器和赋值计数器清零
4. `gettime(1)` 标记计时起点
5. 调用目标排序算法
6. `gettime()` 获取耗时，并读取比较次数与赋值次数
7. `Check()` 校验排序结果是否为升序

### 计数标准

- **比较次数**：仅统计两个数组元素之间的大小比较，如 `a[i] > a[i + 1]`；循环边界、下标递增等不计入
- **赋值次数**：仅统计数组元素之间的赋值；交换两个元素记为 3 次赋值；循环变量赋值不计入

### 字符串排序实验

`SortString.cpp` 对同一组 256 个字符串（64 个单词重复 4 次）分别使用以下存储方式进行冒泡排序：

| 标识     | 存储方式                                | 交换代价             |
| -------- | --------------------------------------- | -------------------- |
| `StrA` | `char str[N][M]` 二维定长数组         | 逐字节复制整行，O(M) |
| `StrB` | `char *str[N]` 指向字符串常量         | 仅交换指针，O(1)     |
| `StrC` | 指针数组，字符串内容动态复制自 `StrA` | 仅交换指针，O(1)     |
| `StrD` | 指针数组，字符串内容动态复制自 `StrB` | 仅交换指针，O(1)     |

比较逻辑统一使用 `strcmp` 的字典序，仅改变元素交换方式，以隔离存储结构对性能的影响。

## 结果与分析

### 1. 执行时间：明显的两个性能梯队

在双对数坐标下：

- 冒泡、选择、插入排序的曲线斜率较陡，呈典型 O(N²) 增长；
- 快速、希尔、桶排序的曲线明显平缓，接近 O(N log N) 或 O(N)。

### 2. 数据分布敏感性差异巨大

- **插入排序**对初始有序性极度敏感：N = 16384 时，完全顺序下耗时约 0.0001 s，完全逆序下约 0.3284 s，劣化超过 3000 倍。
- **选择排序**几乎不受数据分布影响：N = 16384 时始终稳定在 0.17 s ~ 0.19 s，因为其比较次数固定为 N(N−1)/2。
- **桶排序**在均匀、正态分布下表现最佳：N = 16384 时均匀分布约 0.0006 s，正态分布约 0.0005 s。

### 3. 比较与赋值次数的反差

- 选择排序的比较次数最高（与冒泡排序重合），但赋值次数最低，体现“以比较换移动”的设计；
- 插入排序在随机数据下赋值次数最高，主要开销来自大量元素后移；
- 桶排序在均匀分布下的比较次数和赋值次数均处于最低水平。

### 4. 数据类型的影响

- `double` 的排序时间普遍长于 `int`，浮点比较指令的周期成本更高；
- 对 O(N²) 算法，`Score` 结构体的耗时显著高于 `int` / `double`，因为频繁数据移动带来更大的内存拷贝开销；
- 对快速、希尔、桶排序等高效算法，瓶颈转移到比较操作，`Score` 依靠整型比较甚至可以快于 `double`。

### 5. C 字符串存储方式

同样使用冒泡排序，指针数组版本的执行时间仅为二维定长数组的约 30%。两者比较次数相同，差异全部来自交换阶段：

- 二维数组每次交换都需要 `strcpy` 搬运完整字符串，代价与字符串长度相关；
- 指针数组只需交换指针值，本质是 O(1) 的地址赋值。

> 结论：处理长字符串或大体积结构体时，应使用指针数组建立索引进行**间接排序**，避免高昂的数据移动成本。

## 算法选型建议

| 场景                           | 推荐算法            | 理由                                              |
| ------------------------------ | ------------------- | ------------------------------------------------- |
| 小规模或高度有序数据           | 插入排序            | 近乎 O(N)，实现简单，常作为高级排序的底层切换策略 |
| 大规模通用无序数据             | 快速排序 / 希尔排序 | 快排平均性能最优；希尔排序非递归、空间开销小      |
| 分布均匀且特征明确的大规模数据 | 桶排序              | 可突破比较类排序的 O(N log N) 下限，达到线性时间  |
| 大体积结构体 / 长字符串        | 指针数组 + 间接排序 | 只交换地址，避免数据拷贝                          |
